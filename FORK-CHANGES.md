## Included changes

- Interrupted requests retain up to the accepted 50,000-character input limit. Long originals are available through the existing private per-chat archive rather than silently clipped to a recovery prompt; excerpts identify omissions and legacy completeness limits. A second interruption preserves the original task. Chat-mode recovery asks for missing details instead of claiming tool access.
- Scheduled-task deletion fences new dispatches, cancels every matching active handle and waits for cleanup before deleting saved runs. A bounded stop timeout retains the task for retry; overlapping deletion requests retain the fence until their final drain. Editing a schedule during execution remains effective when that run completes.
- Inbox folder/sender changes supersede older list replies. Failed refreshes retain matching rows and offer Retry. Archive/delete failures preserve the message, and partially successful Done updates reload server state instead of reporting a false local outcome. Repeated Done clicks are serialized.
- Task-list failures show an error and Retry instead of a false empty list; failed refreshes retain prior rows and obsolete responses cannot replace a newer load.
- Welcome, accessibility headings and installed-app manifests use NX-Odysseus consistently; upstream license and attribution remain intact.
- Manual chat titles are protected at the database write, including delayed automatic naming and stale cached provenance. Files added while an upload is in flight remain queued for the next send. Compare inventory failures remain errors and retry without caching an empty catalog. Deep workspace paths stay intact in interrupted-run checkpoints.
- Deleting a parent chat fences and cancels its exact team jobs, including requests racing enqueue; uncertain tasks still marked working require inspection and an explicit retry. Unknown model windows show a neutral unknown state, with historical request usage labelled separately. Default Chat and Utility Model saves preserve choice order and HTTP failures. Pending MCP connections close their incomplete transports during shutdown.
- Separate execution workers have an app-side command deadline plus bounded polling grace. Deadline expiry and an unresponsive poll have distinct outcomes, with remote-job cleanup and no local fallback.

- Team runs snapshot each verified child chat's actual model instead of treating participant IDs as model names; changed models still reject queued work. Invalid UTF-8 filenames no longer crash repository inspection: the map marks omissions, retains readable guidance and labels unavailable filenames. Image-setting writes serialize interaction-time snapshots, preserve newer choices and show only the newest save outcome.
- Gallery searches ignore obsolete replies and keep pagination behind the current filter refresh. Initial load failures show an error and Retry; failed refreshes preserve visible photos. Gallery scroll handlers are removed on close. Recovery copy cannot re-enable an explicitly disabled Bash toggle. Repository maps omit ignored untracked artifacts before consuming the display budget, while retaining tracked files and applicable instruction files. Independent evaluation checks stop their POSIX process group on timeout and bound the remaining pipe drain.
- Chat action menus support keyboard activation and Escape focus return without selecting the containing chat row. Failed renames retain the title for retry, concurrent submissions are suppressed, and a completed save preserves newer edits. Folder menus share one outside-click listener instead of adding listeners on every list render.
- Tool-result archiving follows the remaining request budget, including multiple results in one round, so details below the fixed bulk threshold remain recoverable through `context_search`. Cold schema and plan-mode imports use shared lightweight tool types. Separate-worker verification timeouts and orphaned stdout readers stop the check's process group; worker cancellation also discovers nested process groups.
- A document created asynchronously cannot take over another selected document. Managed worktrees cannot be removed while their verification is running; cancellation releases the guard after process cleanup. Changing check definitions during a run makes that result incomplete and stale.
- Context inspection reports the actual request input cap even when the model window is unknown, without exposing prompt content or changing the budget. Image MCP carries the trusted caller owner through model lookup and Gallery storage, rejects spoofed ownerless calls to private providers, and normalizes image failures/results consistently. Generated-image ownership lookup failures return a retryable error instead of serving unverified bytes.
- Browser intent excludes URLs and negated file instructions from workspace coding detection, while keeping later positive coding clauses. The bounded native browser core retains click alongside navigation and snapshot. Unknown model-window budgets remain conservative.
- Graceful shutdown marks active detached runs interrupted before cancellation, preserving explicit continuation and partial output; deliberate Stop remains terminal. Notes drafts survive failed saves and older replies cannot clear a newer draft. Compare export supports keyboard focus and Escape return.
- Document autosaves remain tied to the edited document across tab switches and pane closure. Late document loads cannot select an older request, and save replies preserve edits made while the request was in flight.
- Verification reports become stale when the configured checks change, retaining the prior report as history. Health input loading uses the existing aggregate deadline without blocking the event loop; image-only endpoints report reachability separately from untested generation. Browser-disabled settings cover the full MCP server, including newly added tools.
- PDF exports stop if the pending save fails, preserve editor text and offer a retry rather than exporting stale server content.
- Docker packages the tested Browser MCP CLI and uses system Chromium; startup prefers that installed CLI and keeps npx as the native-install fallback. Locked-down cache-only startup accepts the local executable.
- Subscription-backed endpoint diagnostics resolve account credentials through the normal endpoint resolver. Reconnect-required failures remain controlled categories without exposing tokens or exception text.
- Rapid third-run replacement keeps the original predecessor cleanup barrier even when the middle run never started. Coding requests that cannot retain any enabled coding schema fail before provider dispatch; viable Bash/Python, read-only and disabled-tool paths stay supported.
- Native sidebar and export action buttons preserve existing action IDs. The export popup supports keyboard focus, Escape focus return and outside dismissal. Capability reports use readable sections and keep the complete JSON export; collapsed JSON check edits remain pending for Save.
- The coding evaluator enforces a stream wall-clock budget even with heartbeats, records failed project verification, and preserves reports after independent verification timeouts or evidence-fetch failures. The roadmap now reflects NX priorities and verification limits.

- Project checks now have named fields, explicit argument lines, bounded timeouts and an optional JSON editor. Removing a check preserves edits to other checks. Reports show readable verification results and distinguish waiting for approval, waiting for input, pauses and incomplete verification. Raw reports remain available for copying or download.
- Team autosaves preserve textarea focus and cursor position. Running phases name the active participant and task; builder and reviewer chats are linked from each task. Invalid task titles do not leave the board stuck busy, and late Stop replies cannot update a different chat.
- The approval judge can review bounded edits to common Rust, Go, C/C++, JVM, configuration and frontend source formats, plus Makefile and Dockerfile. This adds eligibility for classification rather than blanket approval. Hidden paths, excluded directories and symlink components remain rejected; execution checks and mandatory snapshots remain in place.

- Harness workflow: bounded applicable repository guidance and file maps, owner-scoped managed Git worktrees, configured verification gates, and a project panel in the workspace picker.
- Coordinated team passes execute server-side with optional task worktrees, saved work and review results, explicit interruption state, matching-child cancellation and human completion. Incognito and delegated credentials cannot launch persisted team passes.
- Stop tracks foreground process groups and background jobs by exact run identity. Separate shell execution is available through an optional restricted worker container.
- Offline capability preflight, bounded owner-scoped run metadata, and a repeatable same-model coding evaluation with independent file assertions.

- Usability pass: ordinary and group chats get a title from the first request immediately. Older model/time and group placeholders show request-derived titles without rewriting their stored names or making bulk model calls. Explicit create/rename titles carry provenance and are preserved, including during asynchronous naming.
- Workspace folders support keyboard activation, loading states and retries; stale navigation replies are ignored. Snapshot controls show the active workspace, prevent duplicate saves and invalidate a restore preview when another snapshot is selected. Disabled actions look disabled; Escape closes the picker and returns focus.
- Approval mode shows loading/saving state, retries failed loading and preserves keyboard focus after a failed save. Participant choices initialize immediately, report provider errors or an empty model list and retry without caching the failure.

- Deleting a chat stops its active agent and waits for archive cleanup/drain before allowing same-ID reuse. Late prepared requests recheck the session; canceled archive workers cannot recreate removed tool context.
- Compare search rerolls preserve the current cancellation controller. Admin Tools saves are queued; reopening waits for saves, and failed changes report an error and reload saved state.
- Rapid approval choices submit directly through the chat form and bypass only the composer debounce. Gated tool proposals show approval state separately from execution results, including after reload; Deny confirms that no action ran. Pending resume requests and readers cancel cleanly when navigating away and cannot insert a reply into another chat.
- Task handles register before dispatch returns. Stop covers queued tasks, and cleanup from an old run cannot release a restarted run's ownership. Chained runs retain deduplication and forced runs retain their existing parallel behavior.
- Full backups pin source directories/files and stream regular files from descriptors. SQLite snapshots verify the database and WAL/SHM descriptors opened by a fresh helper process against pinned identities and retain committed WAL data; mismatched identities fail closed. Excluded model/cache directories are pruned before traversal. File-count and streamed-byte limits stop creation early. Expected export failures provide actionable guidance. Linux procfs is required for SQLite backup creation; Docker provides it. Each database snapshot has a three-minute deadline. This is not an atomic filesystem snapshot.
- A native write to a previously absent file cannot replace a file created concurrently after its initial check.

- Follow-up reliability checks: small input-only caps on known model windows keep their output allowance. Full backups use one file inventory, so a SQLite database created partway through the backup is not copied raw. Detached chat polling retries transient connection/server failures, serializes status requests and ignores stale replies after navigation. Resumed replies retain their personality label.
- Shared frontend module identities now cover model caches, settings, modal registration, tasks, memory, gallery and slash commands. One Settings change saves once. Textarea sizing uses an inert measurement element without duplicate message IDs and copies actual responsive text metrics.
- Late group-board loads cannot replace a newly selected board. Cancelled/retried research ignores stale stream, poll and result responses. Provider error paths redact echoed request credentials, including error frames sent with HTTP 200 and Gemini URL keys, while retaining useful status guidance.
- Native file edits now pin the selected workspace and parent directories, refuse raced links and preserve each file's mode, owner/group and supported user/ACL metadata. Multi-file patches reject duplicate canonical targets and validate hunks before creating missing directories; a later I/O failure explicitly warns that earlier operations may be partial.
- Approval continuations retain their original web-search setting through refresh, mode changes apply tool preferences immediately, and optional web access no longer blocks a coding-only request in a small tool budget. Code filenames such as `probe.py` select edit/test tools even in short requests.
- Snapshot save, preview and restore use the existing worker pool so disk operations don't block streaming or other requests. POSIX workspace restores pin directories and use descriptor-relative reads, writes and removals without following symlinks. Tree traversal errors fail rather than saving partial snapshots. Native platforms without the required safe APIs reject restore; Docker uses the supported Linux path. Restore remains non-atomic against concurrent external file writes.

- General reliability fixes: competing full-backup restore requests are serialized before staging, and restore markers use unique synced temporary files. Output limits now fit each provider route's remaining context after messages and schemas; explicit input caps do not unnecessarily cap output on known models, and unknown backups keep conservative budgets. Coding prompts work when budgeted tool selection omits `get_workspace`. Archived-output search is included in the searchable tool index. Empty Docker embedding URL variables now use the normal endpoint default.
- Group conversations and task boards treat loop, tool-budget and round-limit pauses as incomplete work, retain the reason and stop automatic follow-ups. Research started from chat shares the sidebar's job store. Repeated Start clicks create one session, cancelled queued jobs cannot launch later, and cancellation during a start request attempts to stop the newly created session. Running jobs only show cancelled after confirmation; failures remain visible with a warning. Fallback polling preserves cancellation status.
- Immediate Stop before a detached run starts now closes its checkpoint and wakes subscribers. Snapshot previews show permission changes alongside content changes. Chat, Compare and other renderer users share one ES module instance rather than separate handlers and state.

- Stuck-agent detection checks individual unchanged read/planning results and failed retries across rounds, including narrated calls and changing read limits. Changed outcomes and successful edits reset the counter; polling and human decisions remain excluded. Pauses preserve tool history and edits, keep an explanation after refresh, and prevent automatic teacher takeover. Full-argument digests replace prefix-only signatures in the existing exact-call backstop. The [workflow guide](docs/nx-workflows.md#when-an-agent-goes-in-circles) records thresholds and limits.

- Image-provider settings: Image Generation lists configured image-only providers and recognized image models on mixed providers, including `chatgpt-image-codex`. Values include the endpoint name to avoid collisions. Saved unknown models remain visible; toggles and quality changes no longer erase an unlisted selection. Provider lists refresh on entering AI settings, and the card explains bridge setup, empty inventories and quality/size guidance. Both native and MCP auto-detection use endpoint credentials for the bridge catalog; MCP forwards bridge quality guidance.

- GitHub coding workflow: workspace coding requests prioritize read/edit/shell tools, and later schema allocation budgets against compacted messages rather than raw inspection output. Large reads no longer silently remove unused editors before history compaction. Disabled tools and existing request/native-exchange checks remain enforced. Docker includes ripgrep. Mandatory workspace snapshots allow 8 MiB per file and 64 MiB overall while retaining 2,000-file and 20-snapshot limits.

- URL-routing and toggle clarity: supplied links deterministically select enabled browser entry points when native search/fetch is off or retrieval misses the browser. The magnifying-glass tooltip and explainer now name both search and page fetching. The global `builtin_browser` disable switch applies to all qualified browser actions in schema selection and execution, including tools introduced by later MCP releases.

- Browser selection follow-up: navigation, snapshots and tab access receive priority whenever enabled browser schemas are selected, including retrieved URL requests without forced tools. Tight context budgets no longer depend on the MCP server listing navigation before Close. Disabled-tool filters and execution approvals remain in place.

- Context budgeting follow-up: forced/retrieved tool bundles are bounded rather than exempt, explicit input caps constrain discovery, and browser navigation/inspection are prioritized when requested. Previously used native schemas retain bounded room for subsequent tools. Trimming allocates space for the current question and latest native exchange before a long persona prefix. Unknown windows are labeled unknown instead of zero, and budget errors explain the full assembled prompt rather than blaming a short user message.

- Hermes-inspired native improvements: bounded skill metadata with on-demand procedures/tool activation; usage counted on procedure read, finite confidence and account-threshold publication, draft guidance labeled unverified; multiple owner-scoped recall excerpts per chat, followed by exact message reads in bounded pages with source links/timestamps. Existing personal memory, scheduler, audits and groups are retained. The [comparison](docs/hermes-comparison.md) documents overlap and limits; no Hermes runtime is required.

The UI shows the wait budget and local loading/queue explanation, with pending browser requests cancelled when the check closes. Server-side provider work may continue until its deadline.

- Popup layering: modal auto-promotion happens only when a window opens, preventing visible dialogs from continually raising each other. Compare model/add/swap/export menus follow the live window stack; the scoreboard opens above its parent. Searchable Compare pickers also accept Enter after filtering.
- On-demand web tool selection recognizes requests to find online services, suppresses unrelated retrieval matches and limits MCP descriptions to selected tools. Provider requests bound native schema overhead and reject context shaping that would lose the current question or break a recent native tool exchange.
- Chat progress distinguishes waiting for model output from receiving a response, shows elapsed time, and explains long waits without asserting an unverified cause. Background failures retain their error explanation; saved failures preserve safe, actionable provider error categories after reload.

- Workspace snapshots before coding tools, review diffs, stale-preview rejection, executable permission restoration and pre-restore recovery points. Bounds/exclusions and non-atomic restore limits are documented in the README.
- Opt-in saved group task boards with one builder per task, optional enforced read-only review, human completion, serialized saves and explicit retry for interrupted work.
- Application-data ZIP backups with consistent SQLite copies, streamed/capped upload, safe archive validation, preview, staged startup activation and crash-safe retry. Models/caches/external Docker services are excluded and preserved; existing JSON export/import remains compatible.

- Lightweight Auto approval judge for uncertain public HTTPS page reads and bounded workspace inspections/source edits backed by snapshots. It reuses the current model without tools/history, bounds latency and token use, fails to human approval on uncertainty/errors, and grants only the exact URL within the current run. Arbitrary shell execution, deletions, secret/hidden files, private reads, query payloads, action-like URLs, disabled tools, Ask/plan modes and API-token callers retain their gates. ## Installation and data

The normal installation stays `git clone`, `cp .env.example .env`, then `docker compose up -d --build`. No personal source mounts, host-network workaround, GPU identifier or model download is required for the base setup.

`.env`, data, credentials, chats, generated images, local model configurations, logs and personal installation notes are excluded from Git and Docker build context. Existing upstream GPU overlays remain available. Optional image bridge instructions are in [docs/codex-image-bridge.md](docs/codex-image-bridge.md).
